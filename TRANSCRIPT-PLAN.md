# Speaker turns implementation plan

1. Preserve `Transcript.text`, raw `segments`, transcription adapters, and the numbered-excerpt QA contract. Current whisper-1 segment timestamps do not establish speaker separation.
2. Add separate conversation schemas and a replaceable local role-inference service. Use narrow dispatch/caller language cues conservatively, mark inference as tentative, and leave confidence null because it is not calibrated. Do not infer caller subtype or assign identities based on first/second speaker order. Supplied speaker IDs inform grouping; conflicting role cues for a known ID become UNKNOWN.
3. Group only adjacent matching known IDs (with consistent role) or adjacent matching non-UNKNOWN inferred roles in the two-party model. Never bridge an UNKNOWN segment without identity or a known speaker change. Preserve canonical text exactly via source character spans. If raw segments cannot be aligned losslessly, show the complete canonical text as UNKNOWN and retain raw segments for inspection.
4. Add one nullable JSON `conversation` column through Alembic. New transcripts cache derived data separately using a version and source hash. Existing transcripts derive on read without paid work or database writes. A formatting failure must not fail transcription or QA.
5. Update only the transcript viewer: grouped turns, timestamp ranges/seeking, distinct Dispatcher/Caller/Unknown labels, inference disclosure, and access to raw segments. Keep the audio player and QA views intact.
6. Test grouping, identity boundaries, source preservation, timestamps, unknown/fallback handling, migration compatibility, existing-call reads without provider calls, QA evidence, and retry behavior. Run all backend tests plus frontend lint/type/build and browser checks.
